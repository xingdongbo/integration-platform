# V1 后端包结构与交换引擎说明

## 1. 后端包结构

后端采用 Spring Boot 3 + MyBatis-Plus 分层结构，根包为 `com.company.integration`。

| 包路径 | 职责 |
| --- | --- |
| `com.company.integration.common` | 通用响应、业务异常、全局异常处理、状态常量、基础 CRUD Controller |
| `com.company.integration.config` | MyBatis-Plus 分页等基础配置 |
| `com.company.integration.system` | 系统管理：实体、Mapper、Service、Controller |
| `com.company.integration.api` | 接口配置管理：实体、Mapper、Service、Controller |
| `com.company.integration.header` | Header 配置：实体、Mapper、Service、Controller |
| `com.company.integration.mapping` | 请求/响应映射实体、Mapper、Service、Controller，以及映射引擎 |
| `com.company.integration.executor` | 目标系统 HTTP 调用执行器 |
| `com.company.integration.exchange` | 统一交换入口、交换编排服务、交换结果 DTO |
| `com.company.integration.log` | 交换日志实体、Mapper、Service、Controller |
| `com.company.integration.retry` | 重试任务实体、Mapper、Service、Controller 与人工重试入口 |

## 2. 实体、Mapper、Service、Controller 对应关系

| 功能 | 实体 | Mapper | Service | Controller |
| --- | --- | --- | --- | --- |
| 系统管理 | `SysSystem` | `SysSystemMapper` | `SysSystemService` | `SysSystemController` |
| 接口管理 | `ApiInterface` | `ApiInterfaceMapper` | `ApiInterfaceService` | `ApiInterfaceController` |
| Header 配置 | `ApiHeader` | `ApiHeaderMapper` | `ApiHeaderService` | `ApiHeaderController` |
| 请求映射 | `ApiMappingRequest` | `ApiMappingRequestMapper` | `ApiMappingRequestService` | `ApiMappingRequestController` |
| 响应映射 | `ApiMappingResponse` | `ApiMappingResponseMapper` | `ApiMappingResponseService` | `ApiMappingResponseController` |
| 交换日志 | `ApiExchangeLog` | `ApiExchangeLogMapper` | `ApiExchangeLogService` | `ApiExchangeLogController` |
| 重试任务 | `ApiRetryTask` | `ApiRetryTaskMapper` | `ApiRetryTaskService` | `ApiRetryTaskController` |

所有 Mapper 继承 MyBatis-Plus `BaseMapper`，Service 继承 `IService`，ServiceImpl 继承 `ServiceImpl`，基础 CRUD Controller 复用 `BaseController`。

## 3. 统一交换入口

统一交换入口位于 `ExchangeController`：

```text
POST /exchange/{interfaceCode}
POST /exchange/{interfaceCode}/test
```

执行编排位于 `ExchangeService`，核心流程为：

```text
接收来源请求
  ↓
生成 traceId 并保存 RECEIVED 日志
  ↓
查询接口配置、目标系统、Header、映射规则
  ↓
RequestMappingEngine 执行请求映射
  ↓
ApiExecutor 使用 OkHttp 调用目标系统
  ↓
ResponseMappingEngine 执行响应映射
  ↓
保存 SUCCESS 日志并返回来源响应
```

失败时会保存 `FAILED` 日志，并创建或更新 `api_retry_task` 重试任务。

## 4. 映射引擎

映射实现位于 `com.company.integration.mapping`：

| 类 | 职责 |
| --- | --- |
| `MappingEngine` | 通用字段路径读写与规则执行 |
| `RequestMappingEngine` | 请求映射入口，处理来源请求到目标请求 |
| `ResponseMappingEngine` | 响应映射入口，处理目标响应到来源响应 |

V1 支持以下映射类型：

| 类型 | 说明 |
| --- | --- |
| `FIELD` | 读取 `source_field` 并写入 `target_field` |
| `CONST` | 将 `default_value` 作为固定值写入 `target_field` |
| `DEFAULT` | 来源值为空时使用 `default_value` |
| `EXPRESSION` | 支持简单表达式，例如 `concat(fieldA,'-',fieldB)` 和 `default(value)` |

字段路径支持点号访问，例如：

```text
source_field = data.orderNo
target_field = body.billNo
```

## 5. 人工重试入口

人工重试入口位于 `RetryOperationController`：

```text
POST /retry-operations/{traceId}/retry
```

重试会读取原始交换日志中的 `source_request_raw`，重新执行交换流程，并更新 `api_retry_task` 的重试次数和状态。
