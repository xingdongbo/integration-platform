# 企业数据交换平台开发计划与完成情况

## 1. 文档目的

本文档用于跟踪企业数据交换平台 V1 阶段的功能范围、当前完成情况、未完成事项以及下一步完善计划。

当前项目目标是先完成一套基础可用的数据交换平台，核心价值为：

```text
统一入口
统一转换
统一调用
统一日志
统一重试
```

### 3.2 数据库

已完成 V1 核心表：

- `sys_system`：系统信息表。
- `api_interface`：接口交换配置表。
- `api_header`：Header 配置表。
- `api_mapping_request`：请求映射配置表。
- `api_mapping_response`：响应映射配置表。
- `api_exchange_log`：交换日志表。
- `api_retry_task`：重试任务表。

已包含：

- 主键。
- 唯一索引。
- 常用查询索引。
- 创建时间和更新时间。
- 表注释和字段注释。

### 3.3 后端

已完成基础后端工程：

- Spring Boot 启动类。
- MyBatis-Plus 分页配置。
- MySQL 连接配置。
- 统一响应对象 `ApiResponse`。
- 业务异常 `BusinessException`。
- 全局异常处理 `GlobalExceptionHandler`。
- 状态常量 `StatusConstants`。
- 通用 CRUD Controller `BaseController`。

已完成基础 CRUD 模块：

- `system`：系统管理。
- `api`：接口管理。
- `header`：Header 配置。
- `mapping`：请求 / 响应映射配置。
- `log`：交换日志。
- `retry`：重试任务。

已完成交换核心模块：

- `ExchangeController`：统一交换入口。
- `ExchangeService`：交换流程编排。
- `ApiExecutor`：OkHttp 调用目标系统。
- `MappingEngine`：通用映射执行。
- `RequestMappingEngine`：请求映射入口。
- `ResponseMappingEngine`：响应映射入口。

后端已支持：

- 根据 `interfaceCode` 查询接口配置。
- 校验接口启用状态。
- 校验目标系统启用状态。
- 查询 Header 配置。
- 查询请求映射和响应映射规则。
- 执行请求映射。
- 调用目标系统 HTTP 接口。
- 执行响应映射。
- 保存交换日志。
- 失败时生成或更新重试任务。
- 人工重试失败交换。

## 5. 下一步开发计划

### 5.1 第一优先级：让项目可运行、可验证

1. 在可访问 Maven 仓库的环境中执行后端构建：

   ```bash
   mvn -DskipTests package
   ```

2. 在可访问 npm 仓库的环境中执行前端构建：

   ```bash
   cd frontend
   npm install
   npm run build
   ```

3. 使用 `docs/sql/V1__init_schema.sql` 初始化 MySQL。
4. 启动后端和前端，验证基础 CRUD 页面。
5. 配置一组示例系统、接口、Header、请求映射和响应映射。
6. 通过接口测试页面验证完整交换流程。

### 5.2 第二优先级：补齐基础质量能力

1. 增加后端单元测试：
   - `MappingEngine` 字段路径读写。
   - `FIELD` / `CONST` / `DEFAULT` / `EXPRESSION` 映射。
   - `ExchangeService` 成功和失败流程。
   - 重试流程。
2. 增加前端构建验证。
3. 增加后端参数校验和枚举校验。
4. 增加查询筛选能力。
5. 增加日志脱敏能力。

### 5.3 第三优先级：提升业务可用性

1. 增加业务单号提取配置。
2. 增加自动重试任务调度。
3. 增加接口调用耗时、成功率、失败率统计。
4. 增加更多映射表达式：
   - 日期格式化。
   - 字符串截取 / 拼接。
   - 类型转换。
   - 状态码映射。
5. 增加接口配置导入 / 导出能力。

### 5.4 第四优先级：产品化增强

1. 用户登录和权限管理。
2. 接口版本管理。
3. 配置发布、草稿、回滚。
4. 告警中心。
5. 可视化流程编排。
6. 异步处理和消息队列。

## 6. 当前风险与注意事项

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| 依赖无法下载 | 当前执行 Maven / npm 安装时可能遇到 403 | 使用公司内部 Maven / npm 镜像或可访问公网的环境 |
| 缺少真实联调 | 目前尚未接入真实 ERP / WMS / MES / WCS 接口 | 准备 Mock 服务或测试环境接口 |
| 映射表达式较弱 | 当前表达式能力仅适合简单场景 | 逐步增强表达式函数或引入安全脚本引擎 |
| 日志数据增长 | 交换日志包含原始报文，数据量可能较大 | 后续增加归档、清理和冷热分层策略 |
| 敏感信息 | Header 和报文可能包含 Token、密码、个人信息 | 尽快补充脱敏和访问权限控制 |

## 7. 阶段结论

当前项目已经完成 V1 基础骨架和核心闭环：

```text
配置接口 → 配置映射 → 统一入口调用 → 执行目标接口 → 记录日志 → 失败重试
```

下一步重点不是继续扩展复杂功能，而是先完成真实环境构建、数据库初始化、前后端联调、示例接口验证和自动化测试，确保 V1 基础能力稳定可用。
